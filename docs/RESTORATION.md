# Controlled restoration
Select an authorized online ADB device and a backup root containing manifest.json and data. Confirm the transfer. The engine rejects linked entries, verifies the local manifest, rechecks device authorization, creates a unique Download/DroidLab-Restore directory and pushes the data directory. Existing original folders are not overwritten. A failed transfer can leave partial staged data; no automatic deletion is performed. ADB success is not independent device-side checksum verification. Local backups must be trusted and not modified concurrently. Protected app data and system partitions are excluded. Physical validation remains required.
